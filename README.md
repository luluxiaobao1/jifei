# 【zyun.2609.01】客户侧账单展示调整

360智汇云「费用 > 账单管理」模块客户侧账单展示改版的**高保真原型**。

纯静态 HTML / CSS / 原生 JS，无框架、无构建、无外部依赖。所有数据为本地确定性生成的假数据，仅用于交互与视觉评审。

## 快速开始

浏览器直接打开根目录 `index.html`（唯一入口）。

改动后若页面无变化，请硬刷新：macOS `Cmd+Shift+R` / Windows `Ctrl+Shift+R`。

> 需要在外壳与 iframe 之间调试 `postMessage` 时，`file://` 协议下 Chrome 会阻断跨文档访问，需起本地服务：
> `python3 -m http.server 8000`，然后访问 `http://localhost:8000/index.html`。

## 架构

外壳页用 `iframe` 隔离子视图（样式与脚本互不污染），非首屏视图经 `data-src` 懒加载。子页 `body.subview` 只含 `main-content`，不重复渲染外壳。

三种承载方式各有分工：

| 页面 | 承载 | 入口 |
|---|---|---|
| 账单概览 / 账单详情 | 整页 iframe（`.view-frame`，`shell.js` 的 `VIEW_LABEL` 只含这两个） | 侧边栏 `data-view` |
| 账单分析 | 右侧抽屉 iframe（`embed=1`） | 概览报表账期卡片右侧的入口，经 `postMessage` 请求外壳开抽屉 |
| 计费明细 | 新开页 | 侧边栏 `data-open`，或报表 / 产品分析里的下钻链接（带参数） |

跨 iframe 通信走 `postMessage`：

| 方向 | 消息 | 作用 |
|---|---|---|
| 子页 → 外壳 | `role-change` | 同步顶部角色显示，并广播给其他视图 |
| 子页 → 外壳 | `open-analysis-drawer` / `close-analysis-drawer` | 开关账单分析抽屉 |
| 外壳 → 子页 | `set-role` | 下发当前演示角色 |

所有 CSS / JS 引用带 `?v=` 版本号做缓存刷新。

## 四个页面

| 页面 | 核心用途 | 账期形态 |
|---|---|---|
| **账单概览** | 维度 Tab（企业/结算单元/资源组）× 4 视图：日报表 / 月报表 / 日趋势 / 月趋势 | 报表单选、趋势区间 |
| **账单详情** | 固定资源组维度，逐「资源组 × 产品 × 费用项」展开费用明细 | 单点 |
| **账单分析** | 单账期构成：消费 TOP 卡片 + 产品分析表（按量计费/资源包购买/抵扣/环比） | 单点 |
| **计费明细** | 占位页，新开页打开；带参数时回显条件，侧边栏直接进入则不限定条件 | — |

### 账单概览

维度 Tab 在上，视图分段控件与筛选项**同一行**（32px）：

```
[企业账单] [结算单元账单] [资源组账单]
──────────────────────────────────────────────────────────
(日报表|月报表|日趋势|月趋势) [账期] [组织筛选] [产品] [搜索][重置][导出]
```

**报表视图**（日报表 / 月报表）— 只出表格：

- 上方账期卡片，两段式（详见下节）
- 表格 6 列（+ 维度列）：产品 / 官网标准价金额 / 优惠金额 / 应付金额 / 欠费金额 / 账单状态
- 无操作列；**应付金额数字即下钻入口**，点击新开页进入计费明细
- 列表内不展示合计（已上移至卡片）

#### 账期卡片

```
当前账期 2026.08  ● 出账中                          [📊 账单分析]
──────────────────────────────────────────────────────────────
应付金额合计        欠费金额合计     涉及结算单元      涉及产品
￥124,888,075.29    --              3 个             5 个
↓ 环比 -23.78%      该账期尚未结算   研发部、运营部…   APIMKT、APPMKT…
  （上一账期 2026.07）
```

上排为账期与状态，账单分析入口固定在右端；下排为四个指标格（窄于 1180px 折成 2×2）。

**环比上一账期**：日报表比前一天，月报表比前一月。基数与卡片内「应付金额合计」**同筛选口径** —— 同一批 `scope × 产品`，而非企业全量，否则筛选后两个数对不上。涨为红（花得更多）、跌为绿；上一账期为 0 时显示 `--` 而非除零。

**涉及结算单元**：企业维度取当前角色可见的全部结算单元；结算单元 / 资源组维度由所选主体反查所属结算单元。名称过长时省略，`title` 里给全。

空态（无可查看账单）只保留上排的账期与分析入口，指标区整块省略 —— 无账单则无状态、无金额可言。

**趋势视图**（日趋势 / 月趋势）— 只出曲线图：

- 图例分「总账 / 产品」两组，**逐条点击切换显隐**（键盘回车/空格亦可）
- 总账曲线默认隐藏（量级约等于各产品之和，默认显示会把产品曲线压平）
- 纵轴随可见曲线自动重新贴合
- 鼠标悬停：十字准线 + 浮层列出该账期所有可见曲线的值，多条时附合计

默认账期（演示"今天" = 2026-08-29 14:00）：

| 视图 | 默认 | 区间上限 |
|---|---|---|
| 日报表 | 昨天 `2026.08.28` | — |
| 月报表 | 当前月 `2026.08` | — |
| 日趋势 | 最近 30 天 `2026.07.30 ~ 2026.08.28` | 31 天 |
| 月趋势 | 最近 6 个月 `2026.03 ~ 2026.08` | 12 个月 |

### 账单详情

固定为**资源组维度**，展示当前账号在所选企业下所有有权限的资源组账单。无 Tab、无角色切换栏，数据范围**静默跟随外壳当前角色**（只接收 `set-role`，不向外壳上报）。

行粒度为「资源组 × 产品 × 费用项」，固定 12 列，应付金额可排序。筛选：账单类型 / 账期 / 结算单元（多选，默认全选）→ 资源组（多选，默认全选）/ 产品 / 费用名称 / 费用类型。

## 数据模型

**组织结构**：企业 → 3 个结算单元（研发 42% / 运营 34% / 市场 24%）→ 7 个资源组，每层带权重。三个子页各自持有一份 `ORG` 常量副本（未共享）。

**确定性伪随机**：`pseudo(i, seed)` 基于 `Math.sin`，保证同一账期每次渲染数值不跳动。

**归一化**（概览与分析页）：`sharesAt` / `prodSharesAt` 在同级内归一化，保证

```
Σ结算单元 = Σ资源组 = 企业总额
Σ产品 = 该主体金额
```

因此概览与分析看同一账期时金额可以互相对上（实测误差 0 ~ 1e-9，浮点级）。

**性能兜底**：趋势图产品曲线 TOP20（总账不截断）；TOP 卡片 8 行，超出走弹框。

## 账单状态（概览页报表视图）

| 状态 | 含义 |
|---|---|
| 出账中 | 账期结束后尚未到出账时刻 |
| 未结算 | 已出账，结算未完成（出账后 2~6 小时） |
| 未结清 | 已结算，仍有未结清欠款 |
| 已结清 | 已结算且欠款已还清 |

出账时刻：月账单为**次月 3 日 8:00**；日账单为**次日 14:00**（沿用页面提示条口径，需求未明确给出）。

**账期状态 = 该账期下所有账单状态的汇总**，优先级：

```
出账中 > 未结算 > 未结清 > 已结清
```

即只要有一个账单在出账中，账期即出账中；全部出账后只要有一个未结算即未结算；全部结算后只要有一个未结清即未结清；全部结清才是已结清。

欠费金额在「出账中 / 未结算」时显示 `--`（尚未结算，欠费未知），卡片合计同样显示 `--` 而非按 0 累加 —— 否则会显示「欠费 ￥0.00」，看起来像已结清，属误导。此时卡片在 `--` 下补一句「该账期尚未结算完成」，说明这是未知而非缺数。

## 角色权限（演示用）

| 角色 | 可见范围 |
|---|---|
| 主账号 / 企业管理员 / 系统管理员 | 权限一致，企业下全部账单 |
| 结算单元管理员 | `bu1` `bu2` 及其下全部资源组，无企业账单 |
| 资源组管理员 | 仅指定资源组，无企业 / 结算单元账单 |

角色切换会重置全部筛选、按权限重建下拉选项、切到该角色的默认 Tab。

切换入口是**右下角悬浮按钮**（概览与分析页各一个，样式在 `base.css`，开关行为在 `shared/role-fab.js`）—— 原先是页面顶部一整条黄色横栏，占掉约 60px 首屏高度。按钮上回显当前角色名，点击展开面板选择，选完自动收起；点空白处或 ESC 亦收起。抽屉内的分析页隐藏该按钮，角色由概览页统一切换。

`role-fab.js` 只管开关与角色名回显，切角色仍由各页 `switchRole()` 负责（两页的权限模型与重置逻辑不同，未合并），故须在各页 `app.js` **之后**加载。

资源组管理员的可见资源组为 `rg1`（研发部）、`rg2`（研发部）、`rg5`（运营部），三页一致。跨两个结算单元是有意的 —— 用于演示「资源组权限可跨结算单元」这一情形。

三个子页各自持有一份 `roleConfig` 副本（未共享），改权限需同步改三处：`账单概览/app.js` `账单分析/app.js` `账单详情/app.js`。

## 页面跳转参数

计费明细页均以新开页打开，三个入口：

| 来源 | 参数 |
|---|---|
| 账单概览 > 报表点击应付金额 | `product` `billType` `period` `billingUnit` `resourceGroup` |
| 账单分析 > 产品分析点击计费明细 | `product` `billType` `period` `scope` |
| 外壳侧边栏「计费明细」 | 无参数，条件区为空 |

前两套参数互补，不会同时出现（`scope` 为分析页旧口径，保留以免打断该链路）。无参进入是正常入口而非异常，提示语为「未限定筛选条件，展示全部计费记录……」，不按报错口径写。

## 实现要点

- **draft / applied 双状态**：筛选框的勾选存 `draft`，点「搜索」才写入 `applied` 并重渲染 —— 勾选不会即时刷新结果。
- **各视图账期独立保存**：`dates[view]` / `appliedDates[view]`，切走再切回不丢已选账期；组织与产品筛选则维度内四视图共用。
- **账期控件按视图动态重建**：一个 `.date-ctl` 容器，切视图时重建为「单选 × 日/月」或「区间 × 日/月」，避免 12 套静态筛选栏。
- **图表全手写 SVG**（无图表库）：含 `niceMax` 取整、刻度按**实际文字宽度做重叠检测**（`tickBox` / `GAP`）而非按步长抽稀。
- **悬停浮层是 HTML 而非 SVG 元素**：SVG 用 `preserveAspectRatio="none"` 横向拉伸，文字放进去会变形；浮层须 `pointer-events: none`，否则与 `mousemove` 抢焦点导致闪烁。
- **超范围只报错不自动截断**：日期选择器「确定」时校验，超上限停留在面板内提示，由用户改选。
- **iframe 重绘**：图表依赖真实宽高，切视图 / 开抽屉后在 `requestAnimationFrame` 内派发 `resize` 触发重算。
- **详情页金额扰动种子用全局固定序号 `RG_INDEX`**，而非筛选结果下标 —— 否则同一资源组的金额会随可见范围变化而跳动。

## 已知问题

1. **账单分析入口仅在报表视图可见**：入口在账期卡片右侧，而趋势视图不出账期卡片，故日趋势 / 月趋势下无该入口（改版前挂在 Tabs 行时四视图均可见）。有意保留 —— 账单分析是单账期构成分析，与趋势的多账期口径对不上，入口跟着账期卡片走是自洽的。
